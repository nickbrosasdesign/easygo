# Font Awesome Configuration

Detected by the Font Awesome agent tools. Commit this file so the whole team benefits.

## Integration

- **Method:** React components via `@fortawesome/react-fontawesome`, using individual free SVG icon packages (no Kit — Kit npm packages require a paid-plan package token, which this account doesn't have)
- **Version:** 7.3.1
- **License:** Free
- **Families:** classic (styles: solid, regular, brands)

## Defaults

- **Style:** solid
- **Family:** classic

## Import Pattern

Individual per-icon imports (tree-shakeable, no global `library.add()`):

```jsx
import { FontAwesomeIcon } from '@fortawesome/react-fontawesome'
import { faCheck } from '@fortawesome/free-solid-svg-icons'
// or: from '@fortawesome/free-regular-svg-icons'
// or: from '@fortawesome/free-brands-svg-icons'

<FontAwesomeIcon icon={faCheck} />
```

## Conventions

- No wrapper `<Icon>` component exists yet — `<FontAwesomeIcon>` is used directly.
- The project already has hand-drawn inline `<svg>` icons in several screens/components (e.g. `src/screens/Home.jsx`) predating this setup — these were left as-is. Prefer Font Awesome for new icons going forward rather than adding more inline SVGs, but there's no mandate to migrate existing ones.
- Styling in this repo comes from `public/core.css` design tokens (see root `CLAUDE.md`) — size/color Font Awesome icons via CSS custom properties (e.g. `var(--primitive-blue-400)`) or the component's `size`/`color` props, consistent with existing patterns rather than hardcoded values.

## Note on Kit

The user has a Font Awesome Kit token (`aacb11643e`, free plan) but the free plan doesn't allow Package Manager Tokens, which the Kit's npm package method requires for `.npmrc` registry auth. If the plan is upgraded later, `/setup-fa` can be re-run to switch to the Kit npm package method (custom subsetting, uploaded icons, Pro+ styles). For the React app, the Kit embed script was not used, since the React SVG-package approach is more idiomatic there.

## Static HTML pages (public/easygo-design-system.html, public/easygo-pm-deliverables.html)

These two files are standalone HTML/CSS prototype pages, not part of the Vite build's JS graph (see root `CLAUDE.md`) — the npm/React integration above doesn't apply to them. They use the Kit embed `<script>` tag instead:

```html
<script src="https://kit.fontawesome.com/aacb11643e.js" crossorigin="anonymous"></script>
```

Icons are then plain classic-family solid-style tags, no import needed:

```html
<i class="fa-solid fa-star"></i>
```
